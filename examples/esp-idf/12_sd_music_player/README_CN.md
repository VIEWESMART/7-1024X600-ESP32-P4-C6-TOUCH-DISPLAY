# SD 卡音乐播放示例

本目录播放 SD 卡根目录里的 **MP3** 和 **WAV**。平时是一整页播放界面，从底部向上滑才出现曲目列表。它不播放视频。

和旁边两个视频程序一样，烧录会互相覆盖：

| 目录 | 作用 |
| --- | --- |
| `sd_music_player` | 本示例。播放 MP3 和 WAV |
| `10_7inch_lvgl_demo_v9` | 分屏视频 |
| `sd_video_fullscreen` | 全屏视频 |

屏幕和 SD 卡驱动在本目录的 `components/esp32_p4_s070_wba`。本示例可以单独拷走，不依赖旁边的视频工程。

## 你需要准备

- 10.7 寸板，**ESP32-P4**，PSRAM，Flash **16 MB**
- 屏幕 **JD9165，1024×600，RGB565**
- 喇叭 **NS4168**。MP3 在板子上解开成 PCM，再送给喇叭。板子上没有硬件 MP3 解码器
- **FAT32** SD 卡。不要用 exFAT
- **ESP-IDF v5.5.4**。不要用 v5.4 或 v6.0
- USB 串口。开发时是 `COM3`

## 当前芯片版本

默认按 **ESP32-P4 v3.1 及以上** 编译，CPU **400 MHz**。配套板是 **v3.2**。v3.x 和 v1.x 不能共用同一份固件。

监视器里应看到：

```text
Chip rev:                 v3.2
Minimum supported chip rev: v3.1
```

### 改成在 v1.3 上运行

IDF v5.5.4 没有名为 “v1.3” 的选项。打开 3.0 以下支持，并把最低版本设为 **Rev v1.0**，固件就允许 **v1.0～v1.99**，**v1.3 可以启动**。改完后 v3.2 不能再跑这份固件。

1. 用 VS Code 打开**本目录** `sd_music_player`，`F1` → `ESP-IDF: SDK Configuration Editor (menuconfig)`。或执行 `idf.py menuconfig`。
2. 进入 `Component config → Hardware Settings → Chip revision`。
3. 打开 `Select ESP32-P4 revisions <3.0 (No >=3.x Support)`。
4. 最低版本选 **Rev v1.0**。
5. CPU 用 **360 MHz**。不要打开实验性的 400 MHz 选项。
6. 保存后：

```bat
idf.py fullclean
idf.py build
idf.py -p COM3 flash monitor
```

改回 v3.2：关掉 `<3.0`，最低版本选 **Rev v3.1**，CPU 选 **400 MHz**，再 `fullclean` 后烧录。

## 编译和烧录

第一次编译需要联网。打开的必须是本目录。

```bat
cd 本目录的完整路径
idf.py set-target esp32p4
idf.py build
idf.py -p COM3 flash monitor
```

退出监视器按 `Ctrl+]`。

## SD 卡里放什么

- 卡是 **FAT32**，歌曲放在**根目录**，不要放进子文件夹。
- 本示例**支持长文件名**，`我的歌.mp3` 可以。仍然不要用过长或奇怪的符号。
- 最多列出 **32** 首。
- 支持两种文件：
  - **MP3**。扩展名 `.mp3`。常见的 128 kbps、44.1 kHz 立体声可以。VBR 也能解，但总时长按文件开头的码率估算，拖动进度是近似位置。
  - **WAV**。必须是 PCM、16-bit、单声道或立体声，采样率大约 8 kHz 到 96 kHz。不要用 ADPCM、浮点 WAV 或 24-bit WAV。
- 不认 AAC、FLAC、WMA，也不认放在子目录里的文件。
- 不需要 `video.avi`。视频文件放在这张卡上也不会被这个程序播放。

插卡后重新上电。程序会自己播放列表里的第一首。

## 烧录成功后应该看到什么

屏幕点亮。主体是白色播放页：

- 中间是一个圆，里面是歌名的第一个字母，周围有会动的短条。
- 歌名在圆的下面。下一行是 **SD card**。再下一行类似 **MP3  44 kHz stereo** 或 **WAV  48 kHz stereo**。
- 下面是已播放时间、渐变进度条和总时长。
- 最下面是上一首、播放/暂停、下一首。
- 白色页面的底边有 **ALL TRACKS** 和一条短横线。

有歌曲时，第一首会自动开始，喇叭出声，进度条走动，圆周围的短条会跳动。音量大约是原音量的 40%。

从播放页**向上滑**，白色页面滑上去，深色曲目列表出现。每一行有歌名、**MP3** 或 **WAV**、时长。点一首就播放，列表先保持打开。再从顶部白边**向下滑**，列表收回。

如果根目录没有合格的歌曲，列表里是 **No WAV or MP3 in the SD root.**，标题是 **No music**。这不是死机。

串口会打印找到多少个音频文件，以及正在播放的歌名。采样率和文件不同时，还会打印一行 I2S 频率。

## 需要注意

- 这个程序会替换板上的视频程序。想看视频时，要再去烧录视频那个目录。
- MP3 总时长对 VBR 文件只是估算。进度拖动按文件前后位置估算，不是精确到某一帧。
- WAV 的采样率会改喇叭的 I2S 时钟，所以 44.1 kHz 和 48 kHz 都能按原速播放。
- 播完一首会自动播下一首，到最后一首之后回到第一首。
- 换歌或拖动进度时，喇叭会先清空一下再出声，开头半秒内可能有极短的停顿。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 编译找不到板级组件 | 确认本目录里有 `components/esp32_p4_s070_wba` |
| 芯片版本检查失败 | v1.3 按上一节选 Rev v1.0；v3.2 保持 Rev v3.1。然后 `fullclean` |
| 白屏但没有歌，并写着 No music | 根目录没有 `.mp3` 或合格的 `.wav`，或卡不是 FAT32 |
| 有的 WAV 被跳过 | 它不是 16-bit PCM。用播放器或 ffmpeg 转成 `pcm_s16le` |
| MP3 有列表但没有声音 | 确认喇叭接的是板载 NS4168，并且文件不是空的或损坏的 |
| 时长和手机上差很多 | 多半是 VBR。不影响播放，进度是按文件位置估算的 |
| 上滑没有列表 | 从底部 **ALL TRACKS** 那一条向上滑，不要只点播放键 |
| 端口被占用 | 监视器按 `Ctrl+]` 后再烧录 |
